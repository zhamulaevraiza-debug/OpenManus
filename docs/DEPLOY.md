# Развёртывание OpenManus Web

Это пошаговое руководство поможет запустить OpenManus на собственном сервере и пользоваться им
из браузера на компьютере и телефоне. Опыт администрирования не нужен: каждая команда приведена
целиком, её достаточно скопировать.

> English version: [DEPLOY.en.md](DEPLOY.en.md). Устройство системы: [ARCHITECTURE.md](ARCHITECTURE.md).

**Что вы получите:** сайт с чатом, где команда ИИ-агентов (универсальный Manus, браузер,
исследователь, программист, аналитик данных, автор текстов) выполняет ваши задачи: ищет
информацию, пишет и запускает код, работает с сайтами, строит графики, готовит документы.
У каждого пользователя свои чаты и файлы. Сайт устанавливается на телефон как приложение.

## 1. Что понадобится

| Что | Зачем | Минимум | Рекомендуется |
|---|---|---|---|
| Сервер (VPS) с Linux | здесь работает OpenManus | 2 ядра, 4 ГБ ОЗУ, 30 ГБ диска | 4 ядра, 8 ГБ ОЗУ, 50 ГБ SSD |
| Ключ API языковой модели | «мозг» агентов | OpenAI, Anthropic, OpenRouter, DeepSeek, Google Gemini или своя модель через Ollama | — |
| Доменное имя | HTTPS и установка на телефон | не обязательно для пробы | да, для постоянной работы |

- Подойдёт **Ubuntu 24.04 / 22.04** или **Debian 12**. Команды ниже написаны для них.
- Браузерные агенты запускают Chromium, поэтому памяти нужно больше, чем для обычного сайта.
  На 2 ГБ ОЗУ сборка и работа возможны только с файлом подкачки (см. шаг 4).
- Модель вызывается **с сервера**. OpenAI, Anthropic и Google обслуживают не все страны,
  поэтому важна страна, где находится сервер, а не ваша. Если провайдер недоступен из страны
  сервера, выберите VPS в другой стране (например, в Европе) или провайдера, который там работает.

## 2. Арендуйте сервер (VPS)

VPS — это виртуальный компьютер в дата-центре, который работает круглосуточно. Подойдёт любой
провайдер: Hetzner, DigitalOcean, Vultr, Timeweb Cloud, Selectel, REG.RU и другие.
Обычно это стоит от 5–10 $ в месяц.

При заказе выберите:

1. **Операционную систему:** Ubuntu 24.04 LTS.
2. **Конфигурацию:** не меньше 2 vCPU и 4 ГБ RAM (лучше 8 ГБ), диск от 30 ГБ.
3. **Регион:** с учётом доступности нужной модели (см. выше).
4. **Способ входа:** пароль root или SSH-ключ. Если не знаете, что такое SSH-ключ, выберите пароль.

После создания сервера провайдер покажет его **IP-адрес** (например, `203.0.113.10`) и пароль.
Запишите их. Ниже вместо `203.0.113.10` подставляйте свой IP.

> Если у провайдера есть «облачный файрвол» / «группы безопасности», откройте в нём входящие
> порты **22** (SSH), **80** и **443** (сайт), а на время пробы без домена — **8000**.

## 3. Подключитесь к серверу

Все команды выполняются в терминале сервера через SSH.

- **Windows 10/11:** откройте «Терминал» или PowerShell и введите
  ```bash
  ssh root@203.0.113.10
  ```
- **macOS / Linux:** то же самое в приложении «Терминал».
- **Android:** приложения Termux или JuiceSSH.

При первом подключении ответьте `yes` на вопрос об отпечатке ключа и введите пароль
(символы при вводе не отображаются — так и должно быть). Если провайдер попросит сменить пароль —
придумайте надёжный.

Вставка в терминал: в Windows — правой кнопкой мыши, в macOS — `Cmd+V`, в Linux — `Ctrl+Shift+V`.

## 4. Подготовьте сервер и установите Docker

**Обновите систему:**

```bash
apt update && apt upgrade -y
```

**Если у сервера меньше 4 ГБ памяти**, добавьте файл подкачки на 4 ГБ (иначе сборка может
прерваться из-за нехватки памяти):

```bash
fallocate -l 4G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

**Установите Docker** официальным скриптом:

```bash
curl -fsSL https://get.docker.com | sh
```

Проверьте установку — обе команды должны вывести версии без ошибок:

```bash
docker --version
docker compose version
```

**Файрвол (рекомендуется).** Разрешите SSH и веб-порты и включите файрвол:

```bash
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
```

> **Важно:** порты, опубликованные Docker, обходят правила `ufw`. Порт 8000 будет доступен из
> интернета, пока в `.env` стоит `BIND_ADDRESS=0.0.0.0` (значение по умолчанию). Закрывать его
> нужно через `BIND_ADDRESS=127.0.0.1` после настройки HTTPS (шаг 8), а не через `ufw`.

## 5. Скачайте и запустите OpenManus

**Скачайте код** (если используете другой форк — подставьте его адрес):

```bash
cd ~
git clone https://github.com/zhamulaevraiza-debug/OpenManus.git
cd OpenManus
```

**Создайте файл настроек** из образца:

```bash
cp .env.example .env
```

Для первого запуска в нём ничего менять не нужно. Позже файл можно открыть редактором:
`nano .env` (сохранить — `Ctrl+O`, `Enter`; выйти — `Ctrl+X`). Каждая настройка в нём
снабжена комментарием; полный список — в [разделе 15](#15-справочник-настроек).

**Соберите и запустите:**

```bash
docker compose up -d --build
```

Первая сборка занимает **10–20 минут**: скачиваются Python-библиотеки, Chromium и собирается
веб-интерфейс. Последующие запуски занимают секунды.

**Проверьте состояние:**

```bash
docker compose ps
```

В колонке `STATUS` должно появиться `Up … (healthy)` (в первую минуту там может быть
`health: starting`). Журнал работы:

```bash
docker compose logs -f openmanus
```

(выход из просмотра журнала — `Ctrl+C`, сервер при этом продолжит работать).

Сайт доступен по адресу **`http://203.0.113.10:8000`**.

## 6. Первый вход

1. Откройте `http://203.0.113.10:8000`.
2. Имя пользователя — **`admin`**.
3. Пароль сгенерирован автоматически при первом запуске. Посмотрите его на сервере:
   ```bash
   docker compose exec openmanus cat /data/initial_admin_password.txt
   ```
4. Войдите и **сразу смените пароль**: «Настройки» → «Аккаунт» → «Смена пароля».
5. Удалите файл с первоначальным паролем:
   ```bash
   docker compose exec openmanus rm /data/initial_admin_password.txt
   ```

Свой пароль администратора можно задать заранее: впишите в `.env` строку
`OPENMANUS_ADMIN_PASSWORD=ваш-надёжный-пароль` **до первого запуска**. Он используется
только тогда, когда в базе ещё нет ни одного пользователя.

> Пока сайт открыт по `http://`, пароль передаётся без шифрования. Для постоянной работы
> настройте HTTPS (шаг 8) — это займёт 10 минут.

**Забыли пароль?** Сбросьте его на сервере:

```bash
docker compose exec openmanus python deploy/reset_password.py admin
```

Скрипт попросит ввести новый пароль дважды (или добавьте `--generate`, чтобы получить случайный).
Учётная запись будет разблокирована, а все её сеансы — завершены.

## 7. Подключите языковую модель

Пока модель не подключена, вверху сайта показывается предупреждение. Откройте
**«Настройки» → «Модель»** (раздел виден только администраторам):

1. Нажмите кнопку провайдера в блоке «Готовые настройки провайдеров» — поля «Тип API»,
   «Базовый URL» и «Модель» заполнятся сами.
2. Вставьте **API-ключ**. Ключ хранится только на сервере и больше никогда не показывается
   (видны лишь последние символы). Чтобы заменить ключ, вставьте новый; пустое поле оставляет старый.
3. Нажмите **«Сохранить и проверить»**. Сообщение «Подключено · … мс» означает, что всё работает.

Примеры настроек:

| Провайдер | Тип API | Базовый URL | Модель (пример) | Где взять ключ |
|---|---|---|---|---|
| OpenAI | Совместимый с OpenAI | `https://api.openai.com/v1` | `gpt-4o` | platform.openai.com → API keys |
| Anthropic (Claude) | Совместимый с OpenAI | `https://api.anthropic.com/v1/` | `claude-sonnet-4-6` | console.anthropic.com → API Keys |
| OpenRouter | Совместимый с OpenAI | `https://openrouter.ai/api/v1` | `openai/gpt-4o` | openrouter.ai → Keys |
| DeepSeek | Совместимый с OpenAI | `https://api.deepseek.com/v1` | `deepseek-chat` | platform.deepseek.com → API keys |
| Google Gemini | Совместимый с OpenAI | `https://generativelanguage.googleapis.com/v1beta/openai/` | `gemini-2.5-flash` | aistudio.google.com → Get API key |
| Ollama (своя модель) | Ollama | `http://host.docker.internal:11434/v1` | `qwen2.5:14b` | ключ не нужен (впишите `ollama`) |

Советы по выбору модели:

- Агенты постоянно вызывают инструменты, поэтому модель **должна поддерживать вызов функций
  (tool calling)**. Небольшие модели справляются хуже: для сложных задач берите модели
  уровня GPT-4o, Claude Sonnet, Gemini Pro, DeepSeek-V3.
- Названия моделей меняются — актуальный список смотрите на сайте провайдера; в поле «Модель»
  можно вписать любое название, которое принимает API.
- **Anthropic:** OpenManus передаёт параметры `temperature` и принудительный выбор инструмента
  (`tool_choice`). Если проверка или задачи завершаются ошибкой 400 с упоминанием этих параметров,
  выберите модель, которая их принимает, например `claude-sonnet-4-6`.
- **OpenRouter** даёт доступ к сотням моделей по одному ключу; в названии модели указывается
  компания: `openai/gpt-4o`, `deepseek/deepseek-chat` и т. п. Выбирайте модели с поддержкой Tools.
- **«Работа с изображениями»** — может ли модель видеть картинки (скриншоты браузера, фото
  из чата). По умолчанию определяется по названию модели; если угадано неверно, выберите явно.
  Можно настроить отдельную «Модель для изображений», если основная не умеет работать с картинками.
- **Расходы.** Агент делает много запросов к модели на одну задачу. Установите месячный лимит
  расходов в кабинете провайдера.

### Ollama: модель на своём сервере

Ollama запускает открытые модели локально (нужен мощный сервер, желательно с видеокартой).

1. Установите Ollama на тот же сервер: `curl -fsSL https://ollama.com/install.sh | sh`
2. Скачайте модель с поддержкой инструментов: `ollama pull qwen2.5:14b`
3. Разрешите Ollama принимать подключения из контейнера. Выполните `systemctl edit ollama`,
   добавьте строки
   ```ini
   [Service]
   Environment="OLLAMA_HOST=0.0.0.0"
   ```
   сохраните и выполните `systemctl restart ollama`.
4. Закройте порт Ollama от интернета: `ufw deny 11434/tcp`.
5. В настройках модели выберите «Ollama», базовый URL `http://host.docker.internal:11434/v1`,
   модель `qwen2.5:14b`, ключ `ollama`.

### Настройка через `.env` (необязательно)

Модель можно задать и переменными `OPENMANUS_LLM_*` в `.env` (например, чтобы ключ не хранился в
базе настроек). Такие поля становятся в интерфейсе недоступными для изменения:

```dotenv
OPENMANUS_LLM_BASE_URL=https://api.openai.com/v1
OPENMANUS_LLM_MODEL=gpt-4o
OPENMANUS_LLM_API_KEY=sk-...
```

После правки `.env` примените изменения: `docker compose up -d`.

## 8. Домен и HTTPS

HTTPS шифрует пароли и переписку и **нужен для установки приложения на телефон**, уведомлений
и голосового ввода. В комплекте есть веб-сервер **Caddy**, который сам получает и продлевает
бесплатный сертификат Let's Encrypt.

**1. Купите домен** у любого регистратора (REG.RU, RU-CENTER, Namecheap, Cloudflare, Porkbun…).
Можно использовать поддомен уже имеющегося домена, например `chat.example.com`.

**2. Направьте домен на сервер.** В панели управления DNS у регистратора создайте запись:

| Тип | Имя | Значение |
|---|---|---|
| `A` | `chat` (или `@` для самого домена) | IP вашего сервера, например `203.0.113.10` |

Если у сервера есть IPv6, добавьте ещё запись `AAAA` с IPv6-адресом. Изменения DNS расходятся
от нескольких минут до пары часов. Проверьте командой (должен вывестись IP сервера):

```bash
getent hosts chat.example.com
```

> Если домен обслуживается Cloudflare, на время получения сертификата оставьте у записи режим
> «DNS only» (серое облако).

**3. Впишите настройки в `.env`** (`nano .env`):

```dotenv
DOMAIN=chat.example.com
ACME_EMAIL=you@example.com
BIND_ADDRESS=127.0.0.1
COMPOSE_PROFILES=https
OPENMANUS_COOKIE_SECURE=true
```

- `DOMAIN` — ваш домен; `ACME_EMAIL` — почта для уведомлений Let's Encrypt.
- `BIND_ADDRESS=127.0.0.1` закрывает прямой доступ по порту 8000: сайт будет доступен только через HTTPS.
- `COMPOSE_PROFILES=https` включает Caddy во всех командах `docker compose`.
- `OPENMANUS_COOKIE_SECURE=true` запрещает браузеру отправлять cookie входа по незащищённому соединению.

**4. Примените:**

```bash
docker compose up -d
```

Через минуту откройте `https://chat.example.com`. Ход получения сертификата виден в журнале
`docker compose logs -f caddy`. Для выпуска сертификата порты **80** и **443** должны быть
открыты для всего интернета.

## 9. Установка на телефон и компьютер

OpenManus — прогрессивное веб-приложение (PWA): после установки он открывается с отдельной
иконкой, без адресной строки, как обычное приложение. Нужен HTTPS (шаг 8).

- **Android (Chrome):** откройте сайт → меню **⋮** → **«Установить приложение»**
  (или «Добавить на главный экран»).
- **iPhone / iPad (Safari):** откройте сайт → кнопка **«Поделиться»** (квадрат со стрелкой) →
  **«На экран „Домой“»** → «Добавить».
- **Компьютер (Chrome, Edge):** значок установки в правой части адресной строки.

Подсказка с этими шагами есть в «Настройки» → «О программе».

**Уведомления** о завершении задачи и о вопросах агента включаются в «Настройки» → «Оформление».
На iPhone и iPad уведомления работают только у приложения, установленного на экран «Домой» (iOS 16.4+).

**Голосовой ввод и камера:** кнопки микрофона и камеры в поле ввода сообщения (на телефоне).
Браузер спросит разрешение при первом использовании.

## 10. Пользователи

Администратор управляет учётными записями в **«Настройки» → «Пользователи»**: создаёт
пользователей, назначает администраторов, отключает, сбрасывает пароли и удаляет (вместе с
чатами и файлами). Пользователь видит только свои чаты и файлы; обычным пользователям
недоступны настройки модели и управление пользователями.

**Самостоятельная регистрация** выключена по умолчанию. Её можно включить там же
(«Разрешить самостоятельную регистрацию») или переменной `OPENMANUS_ALLOW_REGISTRATION=true`.
Включайте её только если сайт доступен доверенному кругу людей: агенты выполняют код на вашем
сервере и тратят ваш баланс у провайдера модели (см. [раздел 14](#14-безопасность)).

Ограничения нагрузки: не более `OPENMANUS_MAX_CONCURRENT_RUNS` (4) задач одновременно на весь
сервер и `OPENMANUS_MAX_RUNS_PER_USER` (2) на пользователя.

## 11. Резервные копии

Все данные хранятся в Docker-томе `openmanus_openmanus-data` (внутри контейнера — `/data`):

| Что | Где |
|---|---|
| База данных (пользователи, чаты, история задач) | `/data/openmanus.db` |
| Настройки модели, включая API-ключи | `/data/config/` |
| Файлы чатов (рабочие папки агентов) | `/data/workspaces/` |
| Скриншоты из истории задач | `/data/artifacts/` |
| Ключ подписи сеансов | `/data/secret.key` |
| Журналы | `/data/logs/` |

**Создание копии.** Сервер останавливается примерно на минуту, чтобы база данных была сохранена
целостно:

```bash
cd ~/OpenManus
mkdir -p ~/backups
docker compose stop openmanus
docker compose run --rm --no-deps -T --entrypoint tar openmanus -czf - -C /data . \
  > ~/backups/openmanus-$(date +%F).tar.gz
docker compose start openmanus
```

**Храните копии вне сервера.** Скачать файл на свой компьютер (команда выполняется на
компьютере, а не на сервере):

```bash
scp root@203.0.113.10:~/backups/openmanus-2026-10-04.tar.gz .
```

> Копия содержит API-ключи и хэши паролей — храните её так же бережно, как пароли.

**Автоматическое ежедневное копирование** в 04:00 с хранением 14 последних копий: выполните
`crontab -e` и добавьте строку (одной строкой):

```cron
0 4 * * * cd ~/OpenManus && docker compose stop openmanus && docker compose run --rm --no-deps -T --entrypoint tar openmanus -czf - -C /data . > ~/backups/openmanus-$(date +\%F).tar.gz; docker compose start openmanus; find ~/backups -name 'openmanus-*.tar.gz' -mtime +14 -delete
```

**Восстановление из копии** (текущие данные будут заменены):

```bash
cd ~/OpenManus
docker compose stop openmanus
docker compose run --rm --no-deps -T --entrypoint sh openmanus \
  -c 'find /data -mindepth 1 -delete && tar -xzf - -C /data' < ~/backups/openmanus-2026-10-04.tar.gz
docker compose start openmanus
```

Права доступа к файлам восстанавливаются автоматически при запуске контейнера.

**Перенос на другой сервер:** установите OpenManus на новом сервере (шаги 4–5), перенесите
файл `.env` и копию данных, восстановите копию командой выше.

## 12. Обновление

Перед обновлением сделайте резервную копию (раздел 11). Затем:

```bash
cd ~/OpenManus
git pull
docker compose up -d --build
docker image prune -f
```

Новая версия собирается, пока старая продолжает работать; переключение занимает несколько
секунд. Выполняющиеся задачи при перезапуске прерываются (они получат статус «ошибка» с
пояснением «Server restarted»). Структура базы данных обновляется автоматически.

Если после обновления что-то пошло не так — вернитесь к предыдущей версии:
`git checkout <предыдущий-коммит>` и снова `docker compose up -d --build`
(историю коммитов показывает `git log --oneline`).

## 13. Устранение неполадок

Первое, что стоит сделать при любой проблеме, — посмотреть журнал:

```bash
docker compose ps
docker compose logs --tail 200 openmanus
```

| Проблема | Что проверить |
|---|---|
| Сайт `http://IP:8000` не открывается | `docker compose ps` — контейнер запущен и `healthy`? Открыт ли порт 8000 в облачном файрволе провайдера? Не стоит ли в `.env` `BIND_ADDRESS=127.0.0.1`? |
| Сборка прерывается с `Killed` или `exit code 137` | Не хватает памяти: добавьте файл подкачки (шаг 4). |
| Сборка падает на загрузке пакетов | Временная проблема сети или зеркала — повторите `docker compose build`. За прокси с подменой сертификатов: `docker build --secret id=extra_ca,src=/путь/к/ca.crt -t openmanus-web:latest .` |
| Контейнер постоянно перезапускается | Ошибка в журнале. Частая причина — неверное значение в `.env` (например, `OPENMANUS_SESSION_DAYS=abc`): сообщение `Invalid configuration` укажет переменную. |
| Предупреждение «модель не настроена» | Настройте модель (шаг 7). Ключ-заглушка `YOUR_API_KEY` не считается. |
| «Не удалось подключиться» при проверке модели | Ключ, базовый URL и название модели; баланс у провайдера; доступность провайдера из страны сервера. Для Ollama — `host.docker.internal` вместо `localhost` и `OLLAMA_HOST=0.0.0.0`. |
| Ошибка 429 при входе | 10 неудачных попыток за 10 минут — подождите 10 минут. Сброс пароля — в шаге 6. |
| Не получается войти по `http://` | В `.env` указано `OPENMANUS_COOKIE_SECURE=true` — такая настройка работает только с HTTPS. |
| Сертификат не выпускается | `docker compose logs caddy`. Домен указывает на IP сервера (`getent hosts домен`)? Открыты порты 80 и 443? Заданы `DOMAIN` и `ACME_EMAIL`? Let's Encrypt ограничивает число попыток — после нескольких неудач подождите час. |
| Ход выполнения задачи не обновляется в реальном времени | Если перед OpenManus стоит свой nginx — отключите буферизацию: `proxy_buffering off;` и `proxy_read_timeout 1h;` для `location /api/`. Встроенный Caddy настроен правильно. |
| Загрузка файла: ошибка 413 | Файл больше `OPENMANUS_MAX_UPLOAD_MB` (50 МБ). За своим nginx увеличьте также `client_max_body_size`. |
| Браузерный агент падает или зависает | Не хватает памяти: уменьшите `OPENMANUS_MAX_BROWSERS` или добавьте ОЗУ. |
| Заканчивается место на диске | `docker system df`; очистка старых образов: `docker image prune -f` и `docker builder prune -f`. Файлы чатов занимают место в томе — удаляйте ненужные чаты. |
| Значение с символом `$` в `.env` обрезается | Docker Compose подставляет переменные: заключите значение в одинарные кавычки (`'pa$$word'`). |
| Журналы приложения | `docker compose logs openmanus`; подробные файлы: `docker compose exec openmanus ls /data/logs`. Уровень подробности — `OPENMANUS_LOG_LEVEL=DEBUG`. |

## 14. Безопасность

**Агенты выполняют код.** Агенты пишут и запускают программы на Python и команды оболочки,
открывают сайты и скачивают файлы. Поэтому:

- Давайте доступ **только людям, которым доверяете**. Регистрация по умолчанию выключена —
  оставьте её выключенной на публичном сервере.
- Любой пользователь может потратить ваш баланс у провайдера модели — установите лимиты расходов
  у провайдера и при необходимости уменьшите `OPENMANUS_MAX_RUNS_PER_USER` и `OPENMANUS_RUN_TIMEOUT`.

**Как устроена изоляция:**

- Сервер работает в контейнере с минимальным набором прав Linux (`cap_drop: ALL` плюс шесть
  необходимых возможностей), с запретом повышения привилегий (`no-new-privileges`) и лимитом
  числа процессов.
- Код агентов выполняется от отдельного непривилегированного пользователя `agent` (uid 10001),
  а не от имени сервера. У него нет доступа к базе данных, настройкам, API-ключам, ключу
  сеансов и журналам: эти файлы доступны только серверу.
- Код агентов получает «очищенное» окружение: переменные с ключами, токенами и паролями,
  а также все настройки `OPENMANUS_*` ему не передаются.
- Каждый чат работает в своей рабочей папке со случайным именем; инструменты работы с файлами
  ограничены этой папкой.
- Браузерные инструменты не открывают внутренние адреса (`localhost`, `192.168.x.x`, `10.x.x.x`,
  адреса метаданных облака) — защита от SSRF. Отключается переменной `OPENMANUS_ALLOW_PRIVATE_NETWORK=true`.
- В образе отключена анонимная статистика использования библиотеки browser-use (`ANONYMIZED_TELEMETRY=false`).

**Ограничения, о которых нужно знать:**

- Код всех чатов выполняется от одного и того же пользователя `agent`. Чаты разделены
  случайными, неугадываемыми путями, а не правами операционной системы. Это защита от ошибок,
  но не от злонамеренного пользователя — ещё одна причина пускать только доверенных людей.
- Код агентов (Python, bash) имеет доступ в сеть, включая адреса, доступные самому серверу.
  Не размещайте OpenManus на сервере, с которого доступны чувствительные внутренние сервисы,
  и на облачных машинах с привилегированными сервисными ролями (IAM).
- Не подключайте к контейнеру сокет Docker (`/var/run/docker.sock`): это равносильно правам
  root на сервере. Режим `[sandbox] use_sandbox` из консольной версии в контейнере не используется;
  для изолированного облачного компьютера есть агент «Песочница» (Daytona).

**Рекомендации:**

- Используйте HTTPS (шаг 8) и `OPENMANUS_COOKIE_SECURE=true`.
- Смените первоначальный пароль администратора и удалите файл с ним (шаг 6).
- Регулярно обновляйте систему (`apt update && apt upgrade -y`) и OpenManus (раздел 12).
- Делайте резервные копии и храните их вне сервера (раздел 11).
- Для SSH используйте ключи вместо пароля.

## 15. Справочник настроек

Все настройки задаются в файле `.env` (образец с комментариями — [`.env.example`](../.env.example)).
После изменения выполните `docker compose up -d`.

**Docker Compose**

| Переменная | По умолчанию | Описание |
|---|---|---|
| `OPENMANUS_PORT` | `8000` | Порт сайта на сервере (вне Docker — порт самого приложения) |
| `BIND_ADDRESS` | `0.0.0.0` | Адрес, на котором публикуется порт; `127.0.0.1` — только через HTTPS-прокси |
| `DOMAIN` | — | Домен для профиля `https` |
| `ACME_EMAIL` | — | Почта для Let's Encrypt |
| `COMPOSE_PROFILES` | — | `https` — всегда запускать Caddy |

**Учётные записи и сеансы**

| Переменная | По умолчанию | Описание |
|---|---|---|
| `OPENMANUS_ADMIN_USERNAME` | `admin` | Имя первого администратора |
| `OPENMANUS_ADMIN_PASSWORD` | случайный | Пароль первого администратора (используется, пока нет пользователей) |
| `OPENMANUS_ALLOW_REGISTRATION` | `false` | Самостоятельная регистрация (меняется и в интерфейсе) |
| `OPENMANUS_SECRET_KEY` | из `/data/secret.key` | Ключ подписи сеансов; смена ключа завершает все сеансы |
| `OPENMANUS_SESSION_DAYS` | `14` | Срок действия сеанса, дней |
| `OPENMANUS_COOKIE_SECURE` | `auto` | Флаг Secure у cookie: `auto`, `true`, `false` |

**Ограничения**

| Переменная | По умолчанию | Описание |
|---|---|---|
| `OPENMANUS_MAX_CONCURRENT_RUNS` | `4` | Задач одновременно на весь сервер |
| `OPENMANUS_MAX_RUNS_PER_USER` | `2` | Задач одновременно на пользователя |
| `OPENMANUS_MAX_QUEUED_RUNS` | `16` | Задач в очереди, после чего новые отклоняются |
| `OPENMANUS_RUN_TIMEOUT` | `3600` | Максимальная длительность задачи, секунд |
| `OPENMANUS_HUMAN_INPUT_TIMEOUT` | `1800` | Сколько агент ждёт ответа на свой вопрос, секунд |
| `OPENMANUS_MAX_UPLOAD_MB` | `50` | Максимальный размер загружаемого файла, МБ |
| `OPENMANUS_MAX_BROWSERS` | `3` | Одновременно запущенных Chromium |
| `OPENMANUS_LLM_MAX_CONCURRENCY` | `8` | Одновременных запросов к одному провайдеру модели |

**Модель** (обычно задаётся в интерфейсе; заданные здесь поля в интерфейсе блокируются)

| Переменная | Описание |
|---|---|
| `OPENMANUS_LLM_API_TYPE` | пусто — любой API, совместимый с OpenAI; `azure`, `aws` (Bedrock), `ollama` |
| `OPENMANUS_LLM_BASE_URL`, `OPENMANUS_LLM_MODEL`, `OPENMANUS_LLM_API_KEY` | адрес API, модель, ключ |
| `OPENMANUS_LLM_API_VERSION` | версия API (Azure) |
| `OPENMANUS_LLM_MAX_TOKENS`, `OPENMANUS_LLM_TEMPERATURE` | длина ответа и температура |
| `OPENMANUS_LLM_SUPPORTS_IMAGES` | `true`, `false` или `auto` |
| `OPENMANUS_LLM_VISION_*` | то же для отдельной модели изображений |

**Песочница агентов, прокси и журналы**

| Переменная | По умолчанию | Описание |
|---|---|---|
| `OPENMANUS_ALLOW_PRIVATE_NETWORK` | `false` | Разрешить браузерным инструментам внутренние адреса |
| `OPENMANUS_EXEC_ENV_ALLOWLIST` | — | Доп. переменные окружения для кода агентов (через запятую; секреты не передаются) |
| `OPENMANUS_TRUST_PROXY` | `true` | Доверять заголовкам `X-Forwarded-*` от прокси в частных сетях |
| `FORWARDED_ALLOW_IPS` | частные сети | Адреса прокси, которым доверять (настройка uvicorn) |
| `OPENMANUS_CORS_ORIGINS` | — | Другие сайты, которым разрешено обращаться к API |
| `OPENMANUS_LOG_LEVEL` | `INFO` | Подробность журнала в консоли |
| `OPENMANUS_LOG_FILE_LEVEL` | `DEBUG` | Подробность журнала в файлах |

**Пути и среда выполнения** — задаются образом Docker, менять нужно только без Docker:
`OPENMANUS_DATA_DIR` (`/data`), `OPENMANUS_CONFIG_DIR` (`/data/config`), `OPENMANUS_LOG_DIR`
(`/data/logs`; пустое значение отключает файлы журнала), `OPENMANUS_DATABASE_URL`
(SQLite в каталоге данных), `OPENMANUS_STATIC_DIR` (собранный веб-интерфейс), `OPENMANUS_HOST`
(`0.0.0.0`), `OPENMANUS_BROWSER_HEADLESS` (`true`), `OPENMANUS_EXEC_USER` (`agent`),
`OPENMANUS_WORKSPACE_ROOT` (рабочая папка консольных скриптов).

Настройки поиска, браузера, команды агентов и MCP-серверов меняются в интерфейсе
(«Настройки» → «Поиск и браузер», «Агенты и команда», «MCP-серверы») и хранятся в
`/data/config/config.toml` и `/data/config/mcp.json`.

## 16. Запуск без Docker (для разработчиков)

Нужны Python 3.12 и Node.js 22.

```bash
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python -m playwright install --with-deps chromium

# веб-интерфейс
(cd web && npm ci && npm run build)

# рендерер графиков (агент «Аналитик данных»)
(cd app/tool/chart_visualization && PUPPETEER_SKIP_DOWNLOAD=1 npm ci)

python web_main.py
```

Сайт откроется на `http://localhost:8000`, данные хранятся в `./data`, первоначальный пароль —
в `./data/initial_admin_password.txt`. Для разработки интерфейса с горячей перезагрузкой
запустите в другом терминале `cd web && npm run dev` и откройте `http://localhost:5173`.
Консольные режимы (`python main.py`, `python run_flow.py`, `python run_mcp.py`) работают как раньше.
